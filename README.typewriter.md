# Pomera DM250: Custom SD Card Boot Guide (32MB Compact Layout)

### Summary

INPUT:
 - `idb_loader.bin`: which you can find in github release, and can be generated from `dd if=sd_dm250.img of=idb_loader.bin bs=512 skip=64 count=2048` contains magic number that guide Rockchip to boot from SD card.
 - `uboot_dm250.img`: generated by `make_uboot_image.sh`

OUTPUT:
 - SD Card (128MB for example)
    - 1. first 32MB as hidden, filled with `idb_loader.bin` and `uboot.img`
       - `sudo dd if=idb_loader.bin of=/dev/sda bs=512 seek=64 conv=notrunc,fsync` 
       - `sudo dd if=uboot_dm250.img of=/dev/sda bs=1M seek=8 conv=notrunc,fsync`
    - 2. the rest as FAT32 by `fdisk`

### 1. Core Boot Principle

The Rockchip RK3128 BootROM follows a hardcoded boot sequence when querying external media on a cold start:
* **Sector 64 (`0x8000` / 32 KB) — The Gatekeeper:** The SoC reads this sector looking for a valid Initial Data Block (IDB). It expects the RC4-obfuscated hardware signature **`3b 8c dc fc`**. If this exact magic chunk is absent, the SoC immediately skips the SD card and boots from internal eMMC.
* **Sector 16384 (`0x800000` / 8 MB) — The Payload:** Once the IDB initializes the DDR RAM, the execution chain branches to the 8MB offset to load and execute your `LOADER`-tagged `uboot_dm250.img`.

---

### 2. Disk Layout Map (32MB Hidden Header)

| Sector Range | Byte Offset | Size | Purpose | Source Material |
| :--- | :--- | :--- | :--- | :--- |
| `0 - 63` | `0x0` | 32 KB | MBR Partition Table & Slack | Maintained by system |
| **`64 - 2111`** | **`0x8000` (32 KB)** | 1 MB | **RK3128 Hardware IDB Block** | Extracted `idb_loader.bin` |
| `2112 - 16383` | `0x108000` (~1 MB) | ~7 MB | Safety Padding | Null bytes |
| **`16384 - 24575`** | **`0x800000` (8 MB)** | 4 MB | **U-Boot Slot Payload** | Compiled `uboot_dm250.img` |
| `24576 - 65535` | `0xC00000` (12 MB) | 20 MB | Hidden Tail Margin | Remainder of boot header |
| **`65536 - End`** | **`0x2000000` (32 MB)** | Remainder | **Partition 1 (FAT32)** | Filesystem Storage |

---

### 3. Deployment Execution (Linux)

#### Step A: Shape the 32MB Hidden Header
Wipe the root blocks of the SD card (e.g., `/dev/sda`) and force sector boundary alignments:
```bash
sudo umount /dev/sda* 2>/dev/null
sudo dd if=/dev/zero of=/dev/sda bs=1M count=32 conv=fsync
sudo fdisk /dev/sda
```
Inside the interactive **`fdisk`** prompt, type these keys:
1. **`o`** (Create a fresh MBR/DOS table)
2. **`n`** (New partition)
3. **`p`** / **`Enter`** (Primary type)
4. **`1`** / **`Enter`** (Partition number 1)
5. **`65536`** (Force the first sector to start at exactly 32MB)
6. **`Enter`** (Use remaining space)
7. **`t`** (Change partition type)
8. **`c`** (Select `W95 FAT32 (LBA)`)
9. **`w`** (Write table to disk and exit)

Format the usable volume to FAT32:
```bash
sudo mkfs.vfat -F 32 /dev/sda1
```

#### Step B: Carve and Inject the Binaries

Extract the working hardware key from [sd\_dm250.img](https://www.ekesete.net/pomera/rootfs/sd_dm250.img_20261010.zip) and flash both binaries into their hardcoded locations:

```bash
# 1. Carve the 1MB crypto-key block from the working asset
dd if=sd_dm250.img of=idb_loader.bin bs=512 skip=64 count=2048

# 2. Flash the hardware IDB key into Sector 64
sudo dd if=idb_loader.bin of=/dev/sda bs=512 seek=64 conv=notrunc,fsync

# 3. Flash your compiled U-Boot binary into Sector 16384 (8MB)
sudo dd if=uboot_dm250.img of=/dev/sda bs=1M seek=8 conv=notrunc,fsync
```

---

### 4. Cold-Start Trigger
1. Disconnect all USB-C cables.
2. Hold the **Power** button for **11 seconds** to force a complete deep shutdown.
3. Insert the written 128MB SD card into the slot.
4. Press and hold the **Power** button for **3 to 4 seconds**, then release. The SoC will catch the `3b8cdcfc` magic key at `0x8000` and immediately hand off execution to your custom U-Boot at 8MB.
